## 4. 進化觸發規則

### 時間型
- 任一節 `last_updated` > 90 天 → 對話開頭顯示「⚠️ [節名] 可能過時」
- `cases.md` 最新案例 > 60 天 → 顯示「⚠️ 案例庫該更新了」

### 事件型
- `brand.md` 任一節改動 → 提醒「請重新提煉 `brand-summary.md`」
- 新增資料層（例：未來加 `audience-research.md`） → 強制要求更新 `index.md` 的「載入清單」與「寫入分工矩陣」
- 連續 3 次 AI 引用了大腦裡沒有的資訊 → 觸發「禁止虛構」審查、檢查是不是該節缺料

### 品質型
- 階段 1 完成 → 跑「品質檢查 prompt」、AI 寫 3 支腳本、人工驗收
- 通過 → 解鎖階段 2 的 50 題

## 5. 命名與路徑慣例

- 所有 markdown 檔名小寫、連字號分隔（`brand-summary.md` 而非 `brandSummary.md`）
- 節編號用 `[0]` ~ `[12]` 方括號、子區塊用 `[3.1]` `[3.2]`
- 日期格式統一 `YYYY-MM-DD`
- 案例代號 `CASE-001` ~ `CASE-NNN`、不可重用、刪除留 tombstone
