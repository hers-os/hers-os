> hers-os 的核心架構規格。
> 用途：給 AI 寫短影音腳本時、緣緣是主大腦、references 是不對外的小大腦、最終產出 100% 用緣緣的嘴、骨子滲透 N% 別人的判斷邏輯。

## 0. 一句話定義

> **把別人吃進去、用自己的嘴講出來。觀眾只記得緣緣。**

---

## 1. 核心理念

| 原則 | 說明 |
|---|---|
| **主體唯一** | 緣緣是主大腦、不可被取代、不可被稀釋到面目模糊 |
| **小大腦隱形** | references（楊天真 / 鄧紫棋 ⋯⋯）是思維滲透器、絕對不對外掛名 |
| **嘴是緣緣的** | 產出 100% 用緣緣的口頭禪 / 句法 / 鈎子、不混入別人語感 |
| **骨子可調** | 緣緣的判斷層 + 一點別人的判斷層、比例可控、可審計 |
| **結果反推設計** | 不追求前期完美、靠 feedback loop 校準 6 欄 / 比例 / 借用層 |

---

## 2. 三大鐵律

```
🚫 鐵律 1｜不掛名
   產出腳本不得提及 references 對象的姓名、不得引用其句子
   除非緣緣明確指示「這支要 quote 楊天真」、否則一律隱形

🚫 鐵律 2｜不污染嘴
   references 的口頭禪 / 標誌句不得進入緣緣的腳本
   小大腦只貢獻「判斷層」、不貢獻「表達層」

🚫 鐵律 3｜不無聲偏移
   每支腳本必須記錄使用的 brand.md 版本、references、blend 比例
   每 20 支進行一次累積偏移審查、防止默默變成別人
```

## 5. 各模組角色詳解

### 5.1 主大腦：`01-data-brain/brand.md`

緣緣本人的完整人格說明書、13 節 + 一個必加子節：

| 節 | 用途 | blend 時的角色 |
|---|---|---|
| [0] 基本資料 | 稱呼、平台、頻率 | 給 AI 知道對誰寫 |
| [1] 核心專長 | 差異化、方法論 | **不可被取代** |
| [2] 受眾 | TA 畫像 | **不可被取代** |
| [3] 內容調性 + [3.1] 口頭禪 + [3.2] 禁用詞 + [3.3] 鈎子庫 | 嘴的規則 | **100% 強制套用** |
| [4] 商業洞察 | 變現邏輯 | 影響選題 |
| [5] 禁忌邊界 | 紅線 | **強制過濾** |
| [12.4] 緣緣的身份 6 欄 ⭐ 必加 | 跟 references 同格式 | **blend 的對位基準** |

**[12.4] 結構（與 references 完全一致）**：
```
角色身份：緣緣是 ___ 型的人
服務對象：緣緣主要替 ___ 說話
反對對象：緣緣反對 ___
判斷標準：緣緣判斷一件事好不好、看 ___
使命：緣緣長期想推動 ___、避免 ___
內容邊界：緣緣不應該講 ___、不應該像 ___
```

### 5.4 SKILL：`skills/script-blender/SKILL.md`

Claude Code skill 定義、被呼叫方式：

```
/blend topic="<題目>" blend="<比例>" layers="<借用層>"
```

範例：
```
/blend topic="為什麼我不接低價業配" blend="80:20 緣緣:楊天真" layers="判斷標準,反對對象"
```

skill 內部流程：
1. 讀 `01-data-brain/brand.md` + `brand-summary.md`
2. 讀 `voice/references/楊天真.md` 的 6 欄
3. 讀 `voice/samples/` 金級樣本（語氣鎖定）
4. 套 blend prompt 模板（見 `prompts/default-blend.md`）
5. 產出腳本 → 寫到 `03-scripts/YYYY-MM-DD-XXX-v1.md`、附 metadata
6. 顯示給人看、等審核

## 6. 資料流：從一個題目到一支腳本

```
題目「為什麼我不接低價業配」
        │
        ▼
[1] /blend topic="..." blend="80:20 緣緣:楊天真" layers="判斷,反對"
        │
        ▼
[2] SKILL 載入：
    ├ 主大腦：brand.md ([12.4] 6 欄 + [3] 嘴 + [5] 紅線)
    ├ 小大腦：references/楊天真.md ([判斷] [反對] 兩層)
    └ 嘴：samples/ 金級樣本
        │
        ▼
[3] 套 prompt 模板：
    "用緣緣的嘴（[3] 完整套用）寫，
     判斷邏輯 80% 用緣緣 [12.4]、20% 滲透楊天真 [判斷][反對]，
     觸碰 [5] 紅線立刻停。
     不得提及楊天真姓名、不得引用她的話。"
        │
        ▼
[4] AI 產出腳本 + metadata 區塊：
    ─────────────
    used_brand_md: <commit hash>
    used_references: [楊天真.md@<hash>]
    blend: 80:20
    layers_borrowed: [判斷標準, 反對對象]
    ─────────────
    [腳本本體]
        │
        ▼
[5] 寫入 03-scripts/2026-05-03-低價業配-v1.md
        │
        ▼
[6] 緣緣審核：
    ├ ✅ 像我 → 拍 → 記錄表現
    ├ 🟡 修一下 → 標記哪裡偏 → 改 6 欄或調 blend → /blend ... v2
    └ ❌ 整個歪 → 觸發回推：是哪欄拆得不夠？是主大腦缺料？
```

## 7. Blend 機制（開放設計題 + 我的建議預設）

| 設計題 | 選項 | 建議預設 |
|---|---|---|
| **Q1**「20% 楊天真」是什麼意思 | A 全篇滲透 / B 局部主導 / C 層級制 | **C 層級制**：6 欄選 1-2 層借用、其他層 100% 緣緣 |
| **Q2** 哪幾層可以被借用 | — | ✅ 判斷標準 / 反對對象 / 使命；🚫 服務對象（TA 不變）/ 內容邊界（紅線神聖）/ 角色身份（緣緣是緣緣） |
| **Q3** 多人混要不要支援 | A 支援 / B 一次一個 / C 之後再說 | **C 第一版只做兩方**、確認 work 再擴 |
| **Q4** 比例呼叫方式 | A 文字 / B SKILL 命令 / C 預設 | **B + C**：日常用預設 9:1、SKILL 命令可覆蓋 |

⚠️ 上面是我建議、緣緣可推翻、推翻後寫進這份文件取代。

## 8. Feedback loop（結果反推設計）

### 8.1 每支腳本層級
```
產出 → 審核 → 修哪裡 → 改設計 → /blend v2
                          │
                          ├ 6 欄某欄太抽象 → 進 references/X.md 重寫該欄
                          ├ blend 比例不對 → 調比例
                          ├ 借用層不對 → 換層
                          └ 觸碰紅線 → 進 brand.md [5] 補規則
```

### 8.2 累積偏移層級（每 20 支）
```
一次拉出最近 20 支腳本
    ↓
AI 比對 brand.md 主大腦
    ↓
產出 04-reviews/YYYY-MM-DD-review-NNN.md：
    ├ 集體偏移方向（如有）
    ├ 哪些 references 影響過大
    └ 建議：調主大腦哪節 / 調預設 blend
```

## 9. 啟動前校準包（必填、不可跳）

> ❗ feedback loop 啟動前、緣緣的測量尺要先有刻度。

| 項目 | 必填欄 | 為什麼缺了不能跑 |
|---|---|---|
| brand.md [1] 核心專長 | 全部 | 缺了不知道在講什麼 |
| brand.md [3] 內容調性 + [3.1] 口頭禪 + [3.2] 禁用詞 | 全部 | 缺了「嘴」會跑掉 |
| brand.md [5] 禁忌邊界 | 至少 5 條 | 缺了沒紅線、會默默碰雷 |
| brand.md [12.4] 緣緣的身份 6 欄 | 全部 6 欄 | **缺了沒測量尺、無法判斷產出像不像你** |
| voice/samples/ | 至少 1 個金級樣本 | 缺了 AI 沒有「嘴」可參照 |

✅ 以上完成 → 可以開始跑第一支 blend 腳本
🚫 任一項缺 → SKILL 必須拒絕生成、回報缺料

## 10. 進化與維護規則

| 觸發條件 | 動作 |
|---|---|
| brand.md 任一節改動 | 必須重新提煉 brand-summary.md |
| references/X.md 6 欄改動 | 觸發「過去 20 支用過 X 的腳本」標記為「待重審」 |
| 累積偏移審查發現問題 | 強制更新主大腦或預設 blend、commit message 註明來源 review id |
| 新增 references 對象 | 必須完整填 6 欄 + 至少 1 條 tier-A 引用、否則不入庫 |
| 新增 samples 金級 | 必須附「為何金級」分析、不可只貼原文 |
| 任一節 last_updated > 90 天 | 對話開頭提醒「該節可能過時」 |

## 11. 命名與版本慣例

| 項目 | 慣例 |
|---|---|
| 檔名 | 小寫 + 連字號（`brand-summary.md`） |
| 中文檔名 | references/ 下用本名（`楊天真.md`） |
| 腳本檔 | `YYYY-MM-DD-題目-vN.md`、版本從 v1 起 |
| 案例代號 | `CASE-001` ~ `CASE-NNN`、不重用、刪除留 tombstone |
| 審查代號 | `REVIEW-001` ~ |
| 樣本代號 | 金級 `S-A-NNN` / 銀級 `S-B-NNN` / 銅級 `S-C-NNN` |
| 日期格式 | `YYYY-MM-DD` |
| Git commit | 一次只動一個模組、message 寫清楚 why 不只是 what |
